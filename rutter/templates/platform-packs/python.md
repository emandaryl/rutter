# Platform pack: Python

Detected by: `pyproject.toml`, `uv.lock`, `poetry.lock`, `Pipfile`, `requirements.txt`, or `setup.py` at repo root. This pack is a checklist of what to look for and how to phrase it — write what's actually found, not this pack's wording verbatim.

- **Tech Stack** — check manifest for: Python version (`requires-python` or runtime spec); package/env manager (`uv`, `poetry`, `pipenv`, `conda`, `venv`); web/API framework if any (FastAPI, Django, Flask, Litestar); async model (asyncio/anyio vs synchronous WSGI); ORM/database (SQLAlchemy 2.0, SQLModel, Tortoise ORM, Django ORM, Peewee); test runner (`pytest`, `unittest`); linter/formatter (`ruff`, `black`, `flake8`, `isort`); type checker (`mypy`, `pyright`).
- **Package Structure** — walk `src/<package>/` (or flat top-level `<package>/`); typical folders to expect: `api/` or `routers/`, `models/` or `schemas/` (Pydantic models / ORM entities), `services/` (business logic), `core/` or `config/` (settings, env loading), `db/` (database session, migrations), `tests/`.
- **Architecture Pattern** — for APIs/services: route/endpoint → dependency injection/service layer → repository/ORM query → database; for data pipelines/ML: data ingestion → processing/transforms → model execution → storage/output.
- **Data Layer Conventions** — if SQLAlchemy/SQLModel: async session vs sync session pattern (`async_sessionmaker`, `get_db` generator/dependency), Alembic migration directory (`alembic/` or `migrations/`), whether Pydantic schemas and ORM models are separated. If Django: `models.Model` patterns, custom querysets/managers, migration files.
- **Coding Conventions** — check for: type annotation mandate (strict mypy/pyright), Pydantic validation at boundaries (schemas for request validation and response serialization), custom exception handlers mapped to HTTP status codes, logging conventions (`logging.getLogger(__name__)` or `loguru` wrapper vs raw `print`).
- **Domain Concepts** — read core Pydantic schemas, dataclasses, or ORM model classes for the domain noun hierarchy.
- **Conditional docs signals** — API.md if FastAPI routers, Flask blueprints, Django URLconfs, or GraphQL schemas exist; SECURITY.md if auth dependencies (JWT, OAuth2, passlib/bcrypt, API key middleware) exist; DEPLOYMENT.md if Dockerfile, compose file, or cloud deploy configs exist; TESTING.md if `pytest.ini`, `conftest.py`, or `tests/` directory exists; UI.md only if the project serves templates (Jinja2) or frontend components.
